| ID | BAS-C11 |
| Experiment or failure mode | **Setup work charged to the clock (1.10.1).** The first ponder-on game gate (PLAN "Patch 1.10.1", 2026-09-27, `10+0.1` 1T, Syzygy 3-4-5-6) ran about 130 games of 1.10.1-rc vs 1.10.0 before it was interrupted: 1.10.0 hung ~35 times (BAS-C10), and 1.10.1-rc lost 4 games on time with 27-630 ms left, 2 after a ~1.5-2.3 ms ponderhit and 2 after a ponder miss. **Every** time loss by either engine was in a 5-6-man position. Cause: `start_search` ran `Syzygy::extend_pv` for every best-rank root move, up to 64 plies each, and every ply ran two full root probes (`tb_probe_root` + `tb_probe_root_dtz`), all after `go`/`ponderhit` and before the clock-checked search. Measured on the six losing positions, idle machine, `go wtime 40 winc 100`: **95-297 ms** with Syzygy vs 2-16 ms without, identical on 1.10.0. Rarog, same Fathom library but no line extension, takes 1-3 ms. The extension explains 1.10.0's hangs 48-132 ms after `go ponder` too: in those positions BAS-C10's window was the whole setup, not ~1 ms. A cross-check against Rarog's `9a7b663` (setup work moved off the clock) found two more instances of the same class: the KPK bitbase was built on its first probe inside a search (~10 ms once), and a new `Hash` size / `ucinewgame` / `Clear Hash` was applied inside the first search after `go` (138 ms at 256 MB, ~550 ms at 1 GB). |
| Disposition | **Repaired 2026-09-27; bench unchanged at 14,978,465.** (a) The tablebase line is removed entirely (`extend_pv`, `RootMoveInfo::pv`, the `info` PV and ponder-move overrides); the searched PV and ponder move are used. The root probe, the `searchmoves` filter and the best-rank filter are unchanged, so the move played is unchanged. (b) `init_eval_tables` builds KPK; the probe keeps its `call_once`. (c) `Engine::apply_table_state` resizes and clears when `setoption`/`ucinewgame` is processed, before `readyok`. Same six positions: **3-8 ms**. First KPK search 9.8 -> 0.2 ms; Hash 1024 + `ucinewgame` first move 540 -> 0.4 ms. A new engine test (first search after Hash 512 + `ucinewgame` under 100 ms) fails on the old code; release CTest 12/12, ASan/UBSan CTest 12/12, ponder/threading/protocol/search tests 20/20 repeats, zero-delay ponder stress 0 failures. **Ponder-on gate run 2 (rc3, which also carries BAS-C12): PASS.** In 1,005 games at `3+0.03` 1T, rc3 had 0 failures of any kind, while 1.10.0 had 263 time losses (231 hangs), all in positions of 6 men or fewer. |
| Conditional lesson / coverage | Everything between `go` and the first clock check is spent on the engine's clock, and it is invisible to every harness that sets no `SyzygyPath` and never ponders -- which is all of ours. A cost that "only" affects display (a PV) must still be priced in milliseconds per move, in the positions where it runs. Second: a game gate with a positive control earned its keep twice. It confirmed the fix and found an older, unrelated time-loss defect that the targeted stress test, built from the incident's own hypothesis, could not see. Also noted: the stress test's 6-man FEN was illegal (the side not to move was in check). **Clerical correction, 2026-09-27:** "Basilisk searched it silently", as first written here, is wrong. Basilisk rejected the FEN with an `info string`, then searched the *previous* position, which is BAS-C12. Rarog rejects it and exits. |
