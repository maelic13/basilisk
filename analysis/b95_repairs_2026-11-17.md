## 4. D13: what the Stockfish form does not cover

Fathom given `has_repeated` ranks the wins by DTZ, Stockfish's form. Replaying
game 4965 against the 3-6-man tables showed that this alone does not save the
game.

- At Black's 77th move, the root that preceded the threefold, the shortest
  win is 77...Ke5 (DTZ 78). Its position had stood twice already, so it is
  the threefold. The search filter keeps only the best rank, so Stockfish's
  form plays it, as the head did.
- The added rule: a win after which the position, or the one after any
  reply, stands for the third time ranks as a draw (`allows_threefold`, at
  the root only and only once the game has repeated).
- With the rule the engine plays 77...Rf6. That win is now cursed: DTZ 82
  plus the clock of 20 passes 100 (`cp 49`), so the game was already a draw.
  It was lost earlier.
- At the first root where the game had repeated (ply 151, 76...), the
  repaired engine plays Kd5 and keeps DTZ falling (77, then 76). The game
  played Kf4 into the cycle.
- So the repair is the ranking, applied from the first repetition. The
  threefold rule covers a root that is already in the cycle.
- No gate can measure D13: about one game in 2,286 with tables.
  Recommendation: decide it on this replay and the fixture test, with no
  games. Decided so by the maintainer, 2026-11-17.

## 5. False assumptions found and corrected

- `test_same_colour_bishops`'s fifth position, `1b6/8/8/4K3/8/3b4/8/k7`,
  had its bishops on b8 (dark) and d3 (light). That is the bishop pair, a
  real win (−11,860). B.9.3's packet had quoted that score as the top of
  the same-coloured range. Both were corrected in `59513bb`, against the
  unrepaired head: 5 of 5 positions reproduced.
- B.9.1 expected D13's ranking to make progress in game 4965. It does from
  the first repetition on, but not at the root it measured (§4).
- B.9.1 recorded that the Windows release executable's stack reserve,
  1 MiB, is what a `std::thread` gets. That is confirmed, and the stack
  test's control depends on it.
